# 一、排序查询
在实际开发中，我们经常需要让查询结果按指定的顺序展示，例如：按成绩从高到低排序、按时间从新到旧排序、按价格从低到高排序等。MySQL提供了`ORDER BY`子句来实现排序查询。

## 1.1 基本语法
```sql
SELECT 字段列表 FROM 表名 ORDER BY 字段1 排序方式1, 字段2 排序方式2;
```

## 1.2 排序方式
MySQL支持两种排序方式：
- `ASC`：升序（从小到大），**默认值**，可以省略不写
- `DESC`：降序（从大到小），必须显式指定

## 1.3 多字段排序规则
当需要按多个字段排序时，遵循以下规则：
> 🚨 重要：如果是多字段排序，当第一个字段值相同时，才会根据第二个字段进行排序；如果第一个字段值不同，则直接按第一个字段排序，忽略第二个字段。

## 1.4 排序查询实战示例
基于之前创建的`student`学生表，演示各种排序查询的用法：

```sql
-- 1. 按年龄升序排序（默认升序，ASC可以省略）
SELECT * FROM student ORDER BY age;
SELECT * FROM student ORDER BY age ASC;

-- 2. 按分数降序排序
SELECT * FROM student ORDER BY score DESC;

-- 3. 多字段排序：先按班级升序排序，班级相同再按分数降序排序
SELECT * FROM student ORDER BY class ASC, score DESC;

-- 4. 结合条件查询排序：查询高一1班的学生，按分数降序排序
SELECT * FROM student WHERE class = '高一1班' ORDER BY score DESC;

-- 5. 结合聚合函数排序：统计每个班级的平均分，按平均分降序排序
SELECT class, avg(score) AS 平均分 FROM student GROUP BY class ORDER BY 平均分 DESC;
```

# 二、分页查询
当数据库中的数据量很大时，如果一次性查询所有数据，会导致性能下降、页面加载缓慢，甚至内存溢出。因此，所有的列表展示功能都需要实现分页查询，每次只查询一页的数据。

## 2.1 基本语法
```sql
SELECT 字段列表 FROM 表名 LIMIT 起始索引, 查询记录数;
```

## 2.2 核心计算公式
分页查询中最容易出错的就是起始索引的计算，MySQL的起始索引**从0开始**：
```
起始索引 = (查询页码 - 1) * 每页显示记录数
```

## 2.3 重要注意事项
1. **数据库方言问题**：分页查询是数据库的方言，不同的数据库有不同的实现方式：
   - MySQL：使用`LIMIT`关键字
   - Oracle：使用`ROWNUM`关键字
   - SQL Server：使用`TOP`关键字
2. **第一页简化写法**：如果查询的是第一页数据，起始索引可以省略，直接简写为`LIMIT 查询记录数`
3. **边界情况**：如果最后一页的记录数不足每页显示的记录数，会返回实际存在的记录数，不会报错

## 2.4 分页查询实战示例
假设每页显示3条记录，演示不同页码的分页查询：

```sql
-- 1. 查询第1页数据（每页3条）
SELECT * FROM student LIMIT 0, 3;
-- 第一页简化写法
SELECT * FROM student LIMIT 3;

-- 2. 查询第2页数据
SELECT * FROM student LIMIT 3, 3;

-- 3. 查询第3页数据
SELECT * FROM student LIMIT 6, 3;

-- 4. 结合排序和条件分页：查询分数大于80分的学生，按分数降序排序，每页3条，查询第1页
SELECT * FROM student WHERE score > 80 ORDER BY score DESC LIMIT 0, 3;

-- 5. 结合分组和排序分页：统计每个班级的平均分，按平均分降序排序，每页2条，查询第1页
SELECT class, avg(score) AS 平均分 
FROM student 
GROUP BY class 
ORDER BY 平均分 DESC 
LIMIT 0, 2;
```

# 三、DQL完整语法与执行顺序
到目前为止，我们已经学习了DQL的所有基础语法，现在将它们整合起来，给出完整的DQL语句结构，并讲解其底层执行顺序，这是理解复杂查询的关键。

## 3.1 DQL完整语法
```sql
SELECT 
    字段列表
FROM 
    表名
WHERE 
    分组前过滤条件
GROUP BY 
    分组字段列表
HAVING 
    分组后过滤条件
ORDER BY 
    排序字段列表
LIMIT 
    分页参数;
```

## 3.2 DQL语句执行顺序
这是新手最容易混淆的知识点，也是面试的高频考点。DQL语句并不是按照我们书写的顺序执行的，而是按照以下顺序执行：

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

**执行顺序详解**：
1. `FROM`：先确定要查询的表
2. `WHERE`：过滤原始数据，只保留符合条件的记录
3. `GROUP BY`：将过滤后的数据按指定字段分组
4. `HAVING`：过滤分组后的结果，只保留符合条件的分组
5. `SELECT`：提取指定的字段，计算聚合函数
6. `ORDER BY`：对查询结果进行排序
7. `LIMIT`：对排序后的结果进行分页

> 💡 理解执行顺序的重要性：可以解释为什么`WHERE`不能使用聚合函数（因为`WHERE`在`SELECT`之前执行，聚合函数还没有计算），也可以解释为什么`ORDER BY`可以使用别名（因为`ORDER BY`在`SELECT`之后执行）。

# 四、综合实战演示
下面我们通过一个综合案例，演示条件查询、分组查询、排序查询和分页查询的组合使用。

## 4.1 需求说明
基于`student`学生表，完成以下查询需求：
1. 查询所有年龄大于17岁的学生
2. 按班级分组，统计每个班级的学生人数和平均分
3. 过滤出平均分大于80分的班级
4. 按平均分降序排序
5. 每页显示2条记录，查询第1页

## 4.2 实现代码
```sql
SELECT 
    class AS 班级,
    count(*) AS 学生人数,
    avg(score) AS 平均分
FROM 
    student
WHERE 
    age > 17
GROUP BY 
    class
HAVING 
    avg(score) > 80
ORDER BY 
    平均分 DESC
LIMIT 
    0, 2;
```

## 4.3 执行过程分析
按照DQL的执行顺序，这条语句的执行过程如下：
1. 从`student`表中读取所有数据
2. 过滤出年龄大于17岁的学生
3. 按`class`字段对过滤后的数据进行分组
4. 过滤出平均分大于80分的分组
5. 提取`class`、学生人数和平均分三个字段
6. 按平均分降序排序
7. 取前2条记录作为结果返回

# 五、常见误区与避坑指南
1. **NULL值的排序问题**：MySQL中，NULL值在升序排序时会排在最前面，在降序排序时会排在最后面。如果需要调整NULL值的排序位置，可以使用`IS NULL`函数：
   ```sql
   -- 将NULL值排在最后面（升序）
   SELECT * FROM student ORDER BY email IS NULL, email ASC;
   ```

2. **分页索引错误**：最常见的错误是将起始索引从1开始计算，导致查询结果错误。一定要记住：起始索引 = (页码-1)*每页条数。

3. **大表分页性能问题**：当数据量很大时，`LIMIT 100000, 10`这样的查询会非常慢，因为MySQL需要扫描前100010条记录，然后丢弃前100000条。优化方法是使用主键索引分页：
   ```sql
   -- 优化前
   SELECT * FROM student LIMIT 100000, 10;

   -- 优化后
   SELECT * FROM student WHERE id > 100000 LIMIT 10;
   ```

4. **多字段排序优先级错误**：多字段排序时，前面的字段优先级更高，只有当前面的字段值相同时，才会按后面的字段排序。

5. **LIMIT的参数类型**：LIMIT的两个参数都必须是整数，不能是小数或字符串。

# 六、核心总结：排序与分页查询语法速查表
为了方便后续开发时快速查阅，整理了排序查询与分页查询的核心语法速查表：

| 查询类型    | 语法格式                                            | 核心要点                         |
| ----------- | --------------------------------------------------- | -------------------------------- |
| 升序排序    | `SELECT * FROM 表名 ORDER BY 字段 ASC;`             | ASC是默认值，可以省略            |
| 降序排序    | `SELECT * FROM 表名 ORDER BY 字段 DESC;`            | DESC必须显式指定                 |
| 多字段排序  | `SELECT * FROM 表名 ORDER BY 字段1 ASC,字段2 DESC;` | 前面的字段优先级更高             |
| 基本分页    | `SELECT * FROM 表名 LIMIT 起始索引,记录数;`         | 起始索引从0开始                  |
| 第一页分页  | `SELECT * FROM 表名 LIMIT 记录数;`                  | 第一页可以省略起始索引           |
| 分页公式    | `起始索引 = (页码-1)*每页记录数`                    | 牢记公式，避免索引错误           |
| DQL执行顺序 | `FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT`  | 理解执行顺序是写好复杂查询的关键 |
